# Scientific details and gates
Question: does selecting a matching input span by attention improve tool-call argument accuracy or end-to-end latency over string lookup, without training or special reference tokens?
All arms share model checkpoint, prompt template, examples, EOS/max-new-token policy, dtype and scorer. Original optimized greedy is the speed denominator. Instrumented greedy separately exposes all attention/backend cost. Prefer SDPA plus selected-layer/head last-query QK row; if eager required report its penalty, no hidden comparison to slowed baseline.

Only JSON argument string leaves are eligible. Parse partial output robustly; disallow keys, function names and syntax. Match from the value's first content-prefix, retain source char+UTF-8 byte offsets and prompt-token alignment. Retokenize/verify output-context token continuation; leading-space differences, escaping and Unicode must not be assumed safe from source token ID equality. Default stop before whitespace, quote, backslash, control/uncertain boundary; max 8 draft tokens and 64 chars. If multiple matches, match-only falls back unless continuations identical; attention may disambiguate only with dev-fixed margin/threshold, otherwise fallback. Cover identical prefixes with divergent continuation and repeated full values in fixtures. Restrict copy to prompt spans, not generated output, and disclose this PLD adaptation.

Prefix KV is the actual output context. New tokens are processed at new positions in a causal block; source KV is never grafted. Verified PLD compares candidate[0] to saved prefix-next logits; candidate[i+1] to logits after candidate[i]. Accept only contiguous matching prefix; first mismatch uses target argmax, crop all rejected cache entries before continuing. Handle 0/all/partial acceptance, EOS in accepted/rejected draft and budget truncation. Independently test off-by-one and trim with synthetic logits/cache plus actual model greedy equality. Full token IDs AND EOS/stop reason must match optimized greedy per row. On mismatch preserve all raw evidence and forbid lossless/speed claims until repaired and rerun within scope.

Attention selection quality and practical acceleration are separate. Record trigger count, eligible opportunity denominator, precision vs greedy-compatible next block (and gold-supported correctness separately), example/token coverage, forced-copy wrong tokens/events, mean accepted/forced block length. Report argument exact match, full-call success (name+arguments offline unless actual execution available), JSON validity, greedy token/EOS identity, prefill/decode/total latency, tokenizer/proposal/attention overhead, backend, generated-token counts and invalid/truncated outputs. Never label offline EM as real tool execution success. Include all examples/failures in denominators. Warmup separately and synchronize GPU timings; initialization excluded and disclosed, total includes matching/attention/verification/scoring boundary clearly defined.

Source reuse gate: inspect RefCall license/provenance, original train/dev/test usage and evaluation semantics; do not treat ToolACE training material as held-out. Group by source/template where identifiable and disclose limits. Original instruction model no AttnCopy training, no test-based head/threshold/model selection. Save frozen IDs/config hashes before test, no raw examples in git. If source rights or held-out status cannot be established, report blocker; fixtures are not real pilot replacements.

Related-work primary references (read abstracts/README before seed docs; recheck details):
- LargePiG https://arxiv.org/abs/2410.11366 : training-free pointer-generator mixes attention copy distribution with vocabulary distribution using interlayer vocabulary divergence; AttnCopy selects contiguous JSON-value spans and measures forced vs verified copying.
- LLMA https://arxiv.org/abs/2304.04487 : reference-span drafts checked in parallel to preserve greedy decoding; AttnCopy adds attention selection/forced arms in tool-call strings.
- PLD https://github.com/apoorvumang/prompt-lookup-decoding : n-gram lookup drafts replace neural drafts; verified control uses the same experimental boundary rules, implementation is original unless license permits reuse.
- SwitchSD https://arxiv.org/abs/2609.20186 : trained probes of hidden representations gate copying vs neural drafting; this pilot has no training or neural draft model.
No novelty claims or literature performance numbers are pilot evidence.

Preregistered interpretation: no-go for wider expansion if attention+match has no cost-inclusive advantage over match-only. Selection quality can be encouraging despite negative total speed. Verified equality failure blocks speed conclusion. Small one-model pilot cannot establish general superiority.
